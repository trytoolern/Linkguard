# Проверка в Firefox Desktop 140+

Стек остаётся WXT / Svelte / TypeScript / Tailwind. Firefox — основной target. Сборка должна содержать `background.scripts`, MV3 и Gecko ID; `scripts/check-firefox-manifest.mjs` проверяет это после `npm run build`.

## Подготовка

```sh
npm install
npm run check
npm test
npm run validate:firefox
npm run fixture
```

Оставить fixture запущенным; он напечатает URL вида `http://localhost:PORT/`. Открыть его в Firefox. На `about:debugging#/runtime/this-firefox` загрузить `.output/firefox-mv3/manifest.json` через Load Temporary Add-on. Альтернатива для разработки — `npm run dev` в другом терминале, затем открыть fixture в запущенном WXT Firefox.

## Приёмочный сценарий

1. Нажать «Быстрая проверка». После завершения ожидается **9 уникальных адресов**, **2 Broken**, **2 Unverified**, **1 External**, **1 skipped**. Повтор `/broken#again` должен объединиться с `/broken`.
2. Фильтр Broken показывает 404 и 410. На странице обведены три элемента: две ссылки на `/broken` и одна на `/gone`.
3. Выключить Highlight: обводки исчезают. Включить снова: появляются.
4. Фильтр External показывает только URL на `127.0.0.1`; основная страница открыта на `localhost`.
5. Copy results вставляет TSV выбранного фильтра в текстовый редактор; Export CSV скачивает те же строки. Проверить настоящий буфер обмена и файл.
6. В логе fixture проверить HEAD /head-rejected → GET /head-rejected; 403 и 429 остаются Unverified. Redirect завершается HTTP 200 и сохраняет final URL в CSV.
7. Запустить снова и закрыть popup до завершения `/slow`. Через 5 секунд открыть popup: результат сохранён.
8. Нажать Stop во время `/slow`: скан отменяется, сохраняются готовые результаты. Следующий скан запускается нормально.
9. Сменить страницу во время скана: старый скан прекращается. Результат предыдущей страницы не должен подсвечивать новую.
10. В `about:addons` отозвать доступ к сайтам. Нажать Scan, отклонить запрос: понятное сообщение, запросов к fixture нет. Повторить и разрешить доступ: скан работает.
11. Открыть `about:config` или `addons.mozilla.org`: расширение не должно обещать успешный скан защищённой страницы.
12. Перезапустить Firefox: временное дополнение пропадает. Это штатное поведение временной установки; для постоянной нужна подпись Mozilla.

Инструкции установки: [Mozilla Extension Workshop](https://extensionworkshop.com/documentation/develop/temporary-installation-in-firefox/). Этот документ — план проверки, не утверждение об успешном прохождении.


## Языки

Выбрать по очереди Русский, Español, Français, Deutsch и Татарча в списке справа от LinkGuard. Проверить длинные подписи при ширине 380 px, фильтры, подсветку, сообщения и экспорт. Закрыть и открыть popup: выбор должен сохраниться. Проверить светлую и тёмную тему. CSV/TSV должен содержать переведённые заголовки и ошибки, но исходные URL и HTTP-коды.


## Глубокая проверка

Открыть второй адрес из `npm run fixture`, заканчивающийся `/deep`, и нажать «Глубокая проверка». Ожидается 15 результатов: три «Работает» (`ok`, `redirect`, `slow`), одна битая ссылка (`broken`), две с ограниченным доступом (`challenge`, `login`), девять неопределённых. Подсвечивается только `broken`.

Для `soft404` должна быть причина «Возможная страница ошибки», для `app` — «Нужна проверка в браузере», для `large` — «Превышен лимит HTML». Картинка и форма не загружаются и не отправляются; их наличие отмечается как требующее проверки. В запросах fixture глубокий режим использует GET сразу. Экспорт содержит режим, состояние контента и код причины. Повторить отмену, закрытие popup и навигацию во время `/slow`.

Это сценарий ручной проверки, а не подтверждение её прохождения в текущей среде.


Для ссылки `app` нажать «Проверить в браузере»: должна открыться неактивная вкладка, исполниться скрипт fixture и появиться результат «Работает / Проверено в браузере», после чего временная вкладка закрывается. HTTP-код для нового результата — `—`, поскольку он не измеряется при чтении DOM. Проверить Stop и закрытие popup во время ожидания. Если самому активировать временную вкладку, расширение должно оставить её открытой. Этот сценарий требует настоящего Firefox и не был выполнен в текущей среде.


## Автоматический второй этап

Актуальное поведение: после нажатия «Глубокая проверка» ссылка `app` проверяется в браузере автоматически, без отдельной кнопки. Счётчик браузерного этапа должен обновляться, а phase оставаться scanning до его завершения. Для /deep часть прежних неопределённых результатов автоматически перепроверяется, поэтому итоговое количество статусов нужно оценивать после второго этапа. `ok` и `redirect` не требуют браузерного этапа, `broken` не открывается; `app` должен стать «Работает / Проверено в браузере».

Открыть fixture в двух окнах по очереди и убедиться, что временные вкладки создаются в окне источника. Проверить Stop во время автоматического этапа: временные вкладки закрываются, новые не создаются. Закрытие popup не отменяет проверку. Быстрый режим не должен создавать вкладки. Этот сценарий подготовлен, но не выполнен в настоящем Firefox в данной среде.


## JSON, текст и сообщения ошибок

Открыть адрес `/resources` из `npm run fixture`, нажать глубокую проверку. Из восьми ссылок valid-json и plain-text должны дать «Работает»; bad-json, problem-json, error-json, body-error и attachment-html — неопределённый результат; email-login — ограниченный доступ. Для JSON не должны создаваться вкладки, поле status=404 внутри problem-json не должно менять настоящий HTTP 200. Для attachment-html не должно начинаться автоматическое скачивание. Браузерный этап допускается для body-error и email-login. Это сценарий ручной проверки, не выполненный в настоящем Firefox в текущем прогоне.

## Проверка нового глубокого режима

После `npm run fixture` открыть `/audit` в обычной вкладке, затем выполнить глубокую
проверку. Страница устанавливает только тестовую cookie `fixture_session`.

- `css-hidden`, `empty-main`: «Не удалось проверить / Контент недоступен», не зелёный.
- `delayed`: зелёный только после появления основного текста (fixture ждёт 3,5 секунды).
- `rich-404`: красный, HTTP 404, хотя ответ содержит полноценную статью.
- `session-only`: исходный GET 403, браузерная навигация 200, итог зелёный в том же
  пользовательском сеансе. Повторить в Firefox-контейнере; сначала открыть `/audit`
  именно в нём. Firefox запросит необязательное разрешение cookies для выбора контейнера.
- `soft404`: «Возможная страница ошибки», не зелёный, HTTP 200.

Открыть `/crawl` через hostname **localhost** и выбрать «Сайт и поддомены».
Ожидаются циклы a ↔ b без повторных запросов, один результат `/broken` с двумя
источниками. `/crawl/blocked` запрещён robots.txt; `/logout` пропускается. Адрес
на 127.0.0.1 считается внешним и проверяется без перехода к его дочерним ссылкам.

Во время скана закрыть popup и снова открыть: scope и результаты сохраняются.
Нажать «Остановить» при непустых очередях: новые вкладки не создаются, собственные
неактивные закрываются. Вручную активированная проверочная вкладка остаётся открытой.
Запустить проверки из двух исходных вкладок: общее число временных вкладок не выше 2.

Проверить CSV: исходный GET и наблюдённый HTTP браузера — разные колонки; источники
не теряются. Если HTTP-статус не наблюдался, поле пустое. Эти пункты являются сценарием
ручной приёмки, а не заявлением, что реальный Firefox уже прошёл её в ограниченной среде.

## Проверка перед релизом 0.1.0

- В приватном окне расширение недоступно (`incognito: not_allowed`).
- Страница со ссылками `/logout`, `/unsubscribe`, `/?action=delete`, `/checkout`: оба режима показывают пропуск, без HTTP-запросов и проверочных вкладок. Обычная ссылка рядом продолжает проверяться. Это эвристика по URL, не гарантия отсутствия побочных эффектов произвольного сайта.
- После настройки `project.json` кнопка поддержки открывает `#support` на настоящем сайте; GitHub — настоящий репозиторий. Без настройки соответствующие кнопки скрыты.
- На сайте письмо поддержки получает тему `Support LinkGuard`, обычный контакт — отдельную тему. Отправка только после действия пользователя в почтовом клиенте.
- Страница приватности и оба ZIP скачиваются с сайта без обращения к платёжному API.

## Обновлённая панель запуска

Выбрать режим в списке «Режим проверки», затем нажать «Проверить». Во время проверки список блокируется, на месте запуска появляется «Остановить». Для обхода выбрать «Сайт и поддомены». Фильтры «Все / Битые / Не проверено» сочетаются с отдельным выбором внутренних/внешних ссылок и строкой поиска. До первого скана пустая таблица и действия экспорта скрыты.
